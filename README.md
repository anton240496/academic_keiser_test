## 2. О сайте

Одностраничный приленд для бренда **Keiser University** (бренд из списка ТЗ):

- название и логотип бренда в шапке;
- краткое описание бренда и предложения (секции Hero, «Почему мы», «О нас»);
- полезная для пользователя информация: программы обучения, видео, истории успеха;
- **5 CTA-кнопок** (Hero, карточки программ, «Почему мы», средняя CTA, финальная CTA) — все работают через собственный backend-эндпоинт;
- корректное отображение на десктопе и мобильных устройствах (адаптивная вёрстка).

### Сайт на английском и русском языке

Сайт **двуязычный: английский (EN) + русский (RU)** с переключателем языка в шапке.

Сделано по той причине, что ссылки на примеры из ТЗ (marketerdigital.xyz, topbrandsusa.site) были на английском языке — поэтому контент сайта было решено тоже сделать на английском. Но чтобы сайт был понятнее русскоязычному пользователю, добавлен полный перевод на русский: переключение EN/RU работает для **всего контента** (заголовки, тексты, кнопки, rich-текст «О нас», подвал) без перезагрузки страницы.

Весь контент сайта (тексты на обоих языках) создан с помощью ИИ — это разрешено условиями задания.

Как устроено переключение языков:
- тексты хранятся в базе (Carbon Fields), для каждого поля ключи `*_en` / `*_ru`;
- PHP вставляет значения в JS-объект в header.php;
- JS (assets/js/keiser.js) по клику меняет контент через `data-i18n` атрибуты.

## 4. Инструкция по запуску backend

Backend уже задеплоен публично вместе с прилендом (WordPress на Beget) — отдельный запуск не нужен.

Если требуется развернуть с нуля (локально или на другом хостинге):

1. Установить WordPress.
2. Скопировать папку темы `keiser` в `wp-content/themes/`.
3. Установить плагин **Carbon Fields 3.x** (обязателен — на нём поля админки).
4. Активировать тему «Keiser» в Внешний вид → Темы.
5. Создать страницу с шаблоном **Home** (home.php), назначить её главной (Настройки → Чтение).
6. Таблица `wp_keiser_clicks` создастся автоматически при первом клике — ручных SQL-запросов не требуется (либо импортировать дамп `anton2de_wp_1.sql`).
7. Целевой URL редиректа при необходимости меняется одной строкой в `backend.php` ($official_url).

Проверка backend без клика по кнопке:
- `http://anton2de.beget.tech/?offer=Keiser&sub1=test123` — сохранит клик и сделает 302-редирект на официальный сайт;
- `http://anton2de.beget.tech/clicks` (или `/?action=clicks`) — вернёт JSON со всеми кликами.

## 8. Краткое описание реализованной backend-логики

Цепочка по ТЗ работает полностью: **CTA → Backend → сохранение клика → 302 Redirect → официальный сайт**.

Все CTA-кнопки приленда ведут НЕ напрямую на сайт бренда, а на собственный эндпоинт:
`/?offer=Keiser&sub1=<метка_кнопки>` (например `sub1=hero_cta`, `sub1=program`, `sub1=main_cta`).

Реализация — файл `keiser/backend.php` (подключён через functions.php):

1. **GET /click?offer=<бренд>&sub1=<параметр>** (реализовано как `/?offer=...&sub1=...` — WordPress-совместимый формат):
   - хук `init` перехватывает запрос до вывода страницы;
   - генерируется уникальный `click_id` вида `click_<timestamp>_<случайное_число>`;
   - в БД (таблица `wp_keiser_clicks`) сохраняются: `click_id`, `offer`, `sub1`, `timestamp`, `ip`, `user_agent`;
   - входные параметры очищаются через `sanitize_text_field` (безопасность);
   - выполняется **302 redirect** на `https://www.keiseruniversity.edu`;
   - tracking-параметры передаются и сохраняются без изменений (offer=Keiser, sub1 как в URL).

2. **GET /clicks** — возвращает **JSON** со всеми сохранёнными кликами (свежие сверху); поддерживается и формат `/?action=clicks`.

Пример реального запроса: `http://anton2de.beget.tech/?offer=Keiser&sub1=test123` → клик сохранится с offer=Keiser, sub1=test123 → 302 на keiseruniversity.edu.

В базе данных более 80 записей кликов (таблица `wp_keiser_clicks`; дамп `anton2de_wp_1.sql` можно открыть в phpMyAdmin).
